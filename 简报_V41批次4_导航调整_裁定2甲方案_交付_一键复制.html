二、裁定②甲方案：重复规则「完成后自动新建下一实例」

2.1 语义（按元宝原文）

  • 完成一条带重复规则的日程 → 自动新建下一实例（到期日 = 原到期日 + 一个周期）；
  • 旧实例保留为历史（reminders 表行数会增长——元宝原话：「历史留着才有得捞」）；
  • 撤销完成不回收下一实例（排期不回滚——用户已经看到过这一期）；
  • 不重复的日程 / 无期限提醒 / 系统类（借出到期）→ 不展开。

2.2 展开逻辑为什么挂在数据层（这是本批最关键的一个决定）

概览的「日报签」与「日程签」两处勾选，走的都是 TodoStateWriter.markDone。
展开逻辑若挂 UI 层 → 要在两处各写一遍 → 迟早漂移（违反「口径唯一实现」铁律）。
挂数据层 → 两签天然同源，一份实现两处生效。

落点：InventoryDatabase._expandRepeatingReminder()，由 markDone 与 setReminderDone 两条完成入口都调用——「完成一条带重复规则的日程就产生下一期」是数据层不变量，不该取决于调用方从哪条路进来。两条路都展开，靠幂等查重保证不会建出两条。

2.3 周期推进：唯一实现 + 月末 clamp

推进算法放 lib/domain/repeat_rule.dart（RepeatRule.advance），纯函数、唯一实现；数据层只调不写。

规则推进说明
每天 daily+1 天时分秒原样保留（推进的是日历周期，不是整点偏移）。月末 clamp：1/31 + 1 月 → 2/28（该月最后一天）；2024/2/29 + 1 年 → 2025/2/28。
每周 weekly+7 天
每月 monthly+1 月
每年 yearly+1 年
已知取舍（自曝，请元宝裁示是否接受）：链式推进会逐月漂移——1/31 → 2/28 → 3/28 → 4/28……（每月都从上一实例推进，月末被 clamp 后「锚点」丢了）。
锚点式推进（永远从链条起点算，1/31 → 2/29 → 3/31）需要额外存一列「原始锚点」，会破「schema v13 零新增列」的硬约束，所以本批没做。哪天要修，得单开一个 schema 升级批次。

2.4 幂等：重复完成只建一个下一实例

靠查重实现：同标题 + 同周期 + 同到期日 + 未软删 → 已存在就跳过。

典型链路：完成（建下一实例）→ 撤销（不回收）→ 再完成（查重命中 → 不多建）。

查重不看 status：完成态的权威源是 todo_states，reminders.status 这一列目前不由勾选流程维护，拿它当查重条件会漏判。

2.5 下一实例继承什么

标题 / 备注 / 优先级 / 重复规则全部继承（下一期是同一件事），due_at = 原到期日 + 一个周期，status='pending'，is_deleted=0。

2.6 写边界：只写 reminders 表，账一个字不动

展开只碰 reminders 表（日程系统自己的表），不碰 items / loans / locations / borrowers——「概览改不了账」这条地基不受影响。
源码级锁（v45 新增）：锁②把 _expandRepeatingReminder 方法体单独截出来查，出现任何仓储表常量即失败。
行为级断言：展开前后 getAllLoans() / getAllItems() 长度不变。

2.7 物理分库下的表现

展开在本域那张 reminders 表内完成——生活域完成 → 下一实例落生活库，工作域的库一个数不动（专项已断言）。工作域本轮不开放提醒（能力开关，表建齐但永远为空），所以工作域实际用不到这条路径。

三、配套口径修正：历史实例不该天天挂在催办区

甲方案带出的副作用（我主动发现并修掉的）。
保留历史实例后，历史实例的原到期日在过去 → 催办区的纳入判定第①条「原到期日 ≤ 该日末」会把它判成「逾期」→ 它会天天挂在催办区里，越积越多。
那是「未完成条目的留置规则」被套到了「已完成的历史」上。

3.1 修法

在 TodoAgenda.isInAgenda 加一条前置排除（第⓪条）：

// ⓪ 已完成、且处理时间不在这一天 → 不进该日催办区
if (doneAt != null && doneAt < dayStart) return false;
  • 昨天完成的 → 今天不进催办区（历史实例不再天天挂着）；
  • 今天完成的 → 今天仍然进（日报要看「今天做完了什么」，元宝 B6 口径不动）；
  • 从没处理过的 → 判定与改动前完全一致（逾期留置规则不变）。
改在唯一实现里 → 界面（概览日报签）与导出（日报服务）同源自动生效，不需要在两处各改一遍。
这是本批唯一一处「改了既有判定口径」的改动，请元宝重点复核——它会影响日报导出的条目范围（历史已完成不再天天出现在日报里；当天完成的仍在）。
专项已锁四条（昨天完成不进 / 今天完成进 / 未完成仍进 / 从未处理判定不变）。
